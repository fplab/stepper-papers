\section{Filtered Stepper Calculus}\label{sec:filter}

We now formalize the filter system as the \emph{Filtered Stepper
Calculus}. The key idea is that the stepper carries a \emph{stack} of
the filters in scope while it searches for a redex, and consults them
from innermost to outermost to decide whether to show the step or skip
it silently. A persistent match also leaves a \emph{residue}, an internal marker
around the matched sub-expression that keeps the action in force as
that sub-expression reduces, even once it no longer matches the
pattern. We present the syntax,
contextual dynamics, static semantics, and metatheoretic properties.

\subsection{Syntax}

Each of the four filter primitives in Table~\ref{tbl:primitives}
desugars into a \(\Filter{f}{e}\) expression whose filter
\(f = (p, a, g)\) is the triple of a pattern~\(p\), an action~\(a\),
and a gas~\(g\) described in Section~\ref{sec:examples}. In the calculus, an action is
either \(\ActStep\) (show) or \(\ActSkip\) (hide), and a gas is either
\(\GasOne\) (one-shot) or \(\GasAll\) (persistent).
Table~\ref{tbl:filter-syntax-sugar} gives the desugaring of each
primitive.

\begin{table}[htpb]
  \centering
  \caption{Desugaring of filter primitives.}\label{tbl:filter-syntax-sugar}
  \setlength{\tabcolsep}{8pt}
  \renewcommand{\arraystretch}{1.3}
  \begin{tabular}{ll}
    \toprule
    \textbf{Hazel code} & \textbf{Desugared form} \\
    \midrule
    \verb|debug hide(p) in e| & \(\Filter{(p, \ActSkip, \GasOne)}{e}\) \\
    \verb|debug eval(p) in e| & \(\Filter{(p, \ActSkip, \GasAll)}{e}\) \\
    \verb|debug stop(p) in e| & \(\Filter{(p, \ActStep, \GasOne)}{e}\) \\
    \verb|debug step(p) in e| & \(\Filter{(p, \ActStep, \GasAll)}{e}\) \\
    \bottomrule
  \end{tabular}
\end{table}

A one-shot filter does not fire only once: it stays in scope and is
checked again before every step, so it can match many times, but each
match affects only the step at which it occurs.

The full syntax (Fig.~\ref{fig:filter-syntax}) consists of a small
call-by-value, PCF-style core~\cite{plotkin1977lcf} (functions,
natural numbers, addition, and a fixpoint operator \(\Fix{x}{e}\) for
recursive definitions) together with two filter forms:
\(\Filter{f}{e}\), which the user writes, and
\(\Residue{a}{l}{e}\), which is generated internally by the
stepper. A residue marks a sub-expression where a persistent filter
has already matched, recording the filter's action~\(a\) and its
level~\(l\): the filter's position in the filter stack, counted
from the outside starting at 1. Larger levels give higher priority, and
when several filters and residues apply to a step, the one with the
highest priority decides its action.

Patterns mirror the expression grammar but add two wildcard forms:
\(\PatExpr\), which matches any expression, and \(\PatValue\), which
matches any value.

\begin{figure}[h]
  \begin{equation*}
    \begin{array}{rcl}
      \DefAct a    &\Coloneqq& \ActSkip \mid \ActStep \\
      \DefGas g    &\Coloneqq& \GasOne \mid \GasAll \\
      \DefLvl l    &\Coloneqq& \mathbb{N} \\
      \DefFilter f &\Coloneqq& (p, a, g) \\
      \DefExp e    &\Coloneqq& x \mid e(e) \mid \Lam{x}{e} \mid \Fix{x}{e} \mid e + e \mid \Nat{n} \\
                   &\mid     & \Filter{f}{e} \mid \Residue{a}{l}{e} \\
      \DefPat p    &\Coloneqq& x \mid p(p) \mid \Lam{x}{p} \mid \Fix{x}{p} \mid p + p \mid \Nat{n} \mid \PatExpr \mid \PatValue \\
      \DefCtx \mathcal{E} &\Coloneqq& \Mark \mid \mathcal{E}(e) \mid e(\mathcal{E}) \mid \mathcal{E} + e \mid e + \mathcal{E} \\
                   &\mid     & \Filter{f}{\mathcal{E}} \mid \Residue{a}{l}{\mathcal{E}} \\
      \DefFilterStack \Phi &\Coloneqq& [] \mid f::\Phi \\
    \end{array}
  \end{equation*}

  \label{fig:filter-syntax}
\end{figure}


Values are lambda abstractions and natural-number literals. Fixpoints
are not values: they unroll during evaluation. Filter and residue
wrappers around a value are not values either. They are eliminated by
the instruction transition relation introduced later in this section.

\jbox{\(\Value e\)} Expression \(e\) is a value.
\begin{mathpar}
  \inferrule[V-Lam]{ }{
    \Value{\Lam{x}{e}}
  } \qquad
  \inferrule[V-Nat]{ }{
    \Value{\Nat{n}}
  }
\end{mathpar}

\subsection{Contextual Dynamics by Example}

Each visible step in the stepper is the result of a search for
redexes, \emph{decomposition}, which also matches filters, selects
an action, and maintains residues for each candidate redex. We
introduce decomposition by tracing a small program through the first two
steps, then present the formal rules.

Consider the program

\begin{lstlisting}[language=hazel]
debug eval(1 + 2 + 3 + 4) in
debug stop(3 + 3 + 4) in
1 + 2 + 3 + 4
\end{lstlisting}
\noindent which sums the numbers from 1 to 4 left-associatively. Before
stepping, the stepper starts with the default action \(\ActStep\) at
priority 0, so that every step is shown unless an explicit filter says
otherwise. The explicit filters are assigned priorities sequentially from 
outermost to innermost, so these filters receive priorities 1 and 2.

% In nesting order from outermost to innermost, the two
% explicit filters will receive priorities 1 and 2.
% Outermost gets the lowest priority so that inner filters can
% override outer ones during action selection: as with dynamic binding,
% the innermost filter in effect when a step is taken has the final
% say. Decomposition carries two levels: the \emph{action
% level} \(l_a\), which records the priority that selected the current
% action, and the \emph{residue level} \(l_r\), which records the
% highest residue priority encountered or inserted on the current path.
% Both start at 0.

\paragraph*{First step.}
Entering the filters pushes them onto a stack. At the outermost
addition, \code{(1 + 2 + 3) + 4}, the stepper first tests the priority-2 pattern, 
which does not match, and then the priority-1 pattern, which does.
Since the filter is persistent (i.e. it applies to the full evaluation of
the patten until completion), a residue is inserted around the
whole sum recording the action and priority of the filter that
decided that action for this sub-expression.

The current action is now \(\ActSkip\) with priority $1$. We continue
to traverse through the code until we reach the redex \code{1 + 2}. 
Since we are at priority 1, we now only need to test filters with a
higher priority. The priority-2 filter is tested at the inner additions
but still does not match.

Since decomposition reached the \code{1 + 2} redex with a \(\ActSkip\) action,
this step can be taken silently without user input. The stepper reduces
\code{1 + 2} to \code{3} (\textsc{T-Add}) and plugs
the result into the returned context. With the surrounding filter
prefix elided for brevity, the new expression is:
\begin{lstlisting}[language=hazel]
@\(\prescript{\ActSkip}{}{\langle}\)@3 + 3 + 4@\(\rangle^{1}\)@
\end{lstlisting}
The residue remembers the location of the first match, and that it was a
\(\ActSkip\) action with priority 1, even though the original
\code{1 + 2 + 3 + 4} pattern no longer matches.

\paragraph*{Second step.}
The traversal starts again at the root, rebuilding the filter stack
as it passes through the two filters. It will then reach the residue
where it will restore the skip action record priority 1.

The expression just inside the residue, however, now matches \code{3 + 3 + 4},
Thus we change the action to \(\ActStep\) with priority 2. Since the priority-2
filter is a one-shot action, we do not add a residue.

Decomposition thus yields \(\ActStep\) at \code{3 + 3}, and the stepper
pauses for user input. Once the user decides to step, the stepper transitions
\code{3 + 3} to \code{6}. The priority-1 residue remains on \code{6 + 4},
so the stepper will continue to fully evaluate the rest of the steps in
the original \code{1 + 2 + 3 + 4} expression, having paused only for the
\code{3 + 3 + 4} step.

\subsection{Semantics for Contextual Dynamics}\label{sec:dynamics}

We now present the formal rules that define decomposition, building
up to the top-level stepping judgment.

\subsubsection{Pattern matching.} The matching judgment determines
when a sub-expression's structure conforms to a filter's pattern.
Since filter and residue wrappers are purely instrumental, matching
ignores them (\textsc{M-Filter}, \textsc{M-Residue}). Matching also
ignores bound-variable names: for example, \(\Lam{x}{x}\) and
\(\Lam{y}{y}\) have the same binding structure. In the named
presentation below, corresponding binders are renamed to a common
fresh name before their bodies are compared. The Agda mechanization
represents bound variables with de Bruijn indices, so
\(\alpha\)-equivalent terms require no explicit renaming.

\jbox{\(\Matches{p}{e}\)} Pattern \(p\) matches expression \(e\).
\begin{mathpar}
  \inferrule[M-All]{ }{\Matches{\PatExpr}{e}} \qquad
  \inferrule[M-Val]{\Value{v}}{\Matches{\PatValue}{v}}
  \\
  \inferrule[M-Var]{ }{\Matches{x}{x}} \qquad
  \inferrule[M-Nat]{ }{\Matches{\Nat{n}}{\Nat{n}}}
  \\
  \inferrule[M-Lam]{\Matches{p}{e}}{
    \Matches{\Lam{x}{p}}{\Lam{x}{e}}} \qquad
  \inferrule[M-Fix]{\Matches{p}{e}}{
    \Matches{\Fix{x}{p}}{\Fix{x}{e}}}
  \\
  \inferrule[M-Ap]{\Matches{p_1}{e_1} \\ \Matches{p_2}{e_2}}{
    \Matches{p_1(p_2)}{e_1(e_2)}} \qquad
  \inferrule[M-Add]{\Matches{p_1}{e_1} \\ \Matches{p_2}{e_2}}{
    \Matches{p_1+p_2}{e_1+e_2}}
  \\
  \inferrule[M-Filter]{\Matches{p}{e}}{
    \Matches{p}{\Filter{f}{e}}} \qquad
  \inferrule[M-Residue]{\Matches{p}{e}}{
    \Matches{p}{\Residue{a}{l}{e}}}
\end{mathpar}

\subsubsection{Stripping.} The strip operation erases all filter and
residue wrappers from an expression. It is used to state simulation
(Theorem~\ref{thm:simulation}).

\jbox{\(\Strip{e} = {e'}\)} Strip filter and residue wrappers from expression \(e\).
\[
  \begin{aligned}
    \Strip{x} &= x \\
    \Strip{\Lam{x}{e}} &= \Lam{x}{\Strip{e}} \\
    \Strip{(e_1(e_2))} &= (\Strip{e_1})(\Strip{e_2}) \\
    \Strip{\Nat{n}} &= \Nat{n} \\
    \Strip{(e_1 + e_2)} &= (\Strip{e_1}) + (\Strip{e_2}) \\
    \Strip{(\Filter{f}{e})} &= \Strip{e} \\
    \Strip{\Residue{a}{l}{e}} &= \Strip{e} \\
    \Strip{\Fix{x}{e}} &= \Fix{x}{\Strip{e}}
  \end{aligned}
\]

\subsubsection{State.} We introduce the notion of a \emph{state}
\(s=(a,l_a,l_r,\mathcal{E})\) to record the information carried
while searching for a redex. Here, \(a\) is the current
action, \(l_a\) is the level at which action~\(a\) was selected,
\(l_r\) is the highest level of a residue encountered or inserted
along the current candidate path, and \(\mathcal{E}\) is the
candidate context. The stack \(\Phi\) contains the filters in scope
at the current expression, innermost first.

The inspected expression sits in the hole of \(\mathcal{E}\).
Write \(\Plug{\mathcal{E}}{e}\) for filling this hole with an
expression, and \(\Plug{\mathcal{E}}{\mathcal{E}_0}\) for filling
it with another context (Appendix~\ref{sec:standard_rules}). The
search starts with an empty filter stack and the default state
\(s_0=(\ActStep,0,0,\Mark)\); we write
\(\TopState=([],s_0)\).

\subsubsection{Action selection.} The function
\(\Lookup{\Phi}{e}{s}\) looks up filters in \(\Phi\) whose patterns
match \(e\), updating \(s\) using their actions and gas.
The action level \(l_a\) determines whether a matching filter can
override the current action; the residue level \(l_r\) determines
which levels are already covered by a residue.
The head filter of \((p,a_f,g)::\Phi\) has
action~\(a_f\) and level \(l_f=1+|\Phi|\). The helper
\(\mathsf{bump}\) compares the current pair \((a,l_a)\) with the
filter's pair \((a_f,l_f)\):
\[
  \Bump{(a,l_a)}{(a_f,l_f)} =
  \begin{cases}
    (a_f,l_f) & \text{if } l_f>l_a,\\
    (a,l_a) & \text{if } l_f\leq l_a.
  \end{cases}
\]
\jbox{\(\Lookup{\Phi}{e}{s}=s'\)}
Scanning filter stack \(\Phi\) against expression \(e\) updates
state \(s\) to \(s'\).

The stack is scanned from innermost to outermost. An empty stack
or a level already covered by \(l_r\) ends the
scan; a non-matching filter is passed over.
\begin{mathpar}
 \inferrule[L-Empty]{ }{\Lookup{[]}{e}{s}=s}
 \qquad
 \inferrule[L-Cut]{l_f\leq l_r}{\Lookup{(p,a_f,g)::\Phi}{e}{s}=s}
 \\
 \inferrule[L-Miss]{l_f>l_r \\ \neg(\Matches{p}{e})}{
   \Lookup{(p,a_f,g)::\Phi}{e}{s}=\Lookup{\Phi}{e}{s}}
\end{mathpar}

A one-shot match (\(g=\GasOne\)) uses \(\mathsf{bump}\) to update the action and
its level, then continues scanning with the same residue level
and context. A persistent match (\(g=\GasAll\)) updates the action in the same way,
adds a residue carrying the filter's own action~\(a_f\), and ends
the scan.
\begin{mathpar}
 \inferrule[L-One]{
   l_f>l_r \\ \Matches{p}{e} \\
   \Bump{(a,l_a)}{(a_f,l_f)}=(a',l_a')
 }{\Lookup{(p,a_f,\GasOne)::\Phi}{e}{s}
    =\Lookup{\Phi}{e}{(a',l_a',l_r,\mathcal{E})}}
 \\
 \inferrule[L-All]{
   l_f>l_r \\ \Matches{p}{e} \\
   \Bump{(a,l_a)}{(a_f,l_f)}=(a',l_a')
 }{\Lookup{(p,a_f,\GasAll)::\Phi}{e}{s}
    =(a',l_a',l_f,\Plug{\mathcal{E}}{\Residue{a_f}{l_f}{\Mark}})}
\end{mathpar}

For example, suppose an inner level-2 \code{debug stop(\$e)} and an
outer level-1 \code{debug eval(\$e)} both match the current
addition, starting with both levels at zero. \textsc{L-One} selects
\(\ActStep\) at action level 2, then \textsc{L-All} records the
outer filter's \(\ActSkip\) at residue level 1. Lookup returns
\(a'=\ActStep\), \(l_a'=2\), and \(l_r'=1\), with the residue
inserted into the returned context.

\subsubsection{Decomposition.} Decomposition of \(e\) produces a
context--redex pair \(\mathcal{E}'\{e_0\}\) with action \(a'\)
at level \(l_a'\). Decomposition is
non-deterministic: when an expression has multiple redexes (e.g., both
operands of an addition are reducible), there is a choice of which to
expose.

We define a helper function \(\mathsf{keep}\) to decide whether
to retain a residue in the context:
\[
  \Keep{l_r}{(a_r,l)}{\mathcal{E}} =
  \begin{cases}
    \Plug{\mathcal{E}}{\Residue{a_r}{l}{\Mark}}
      & \text{if } l>l_r,\\
    \mathcal{E} & \text{if } l\leq l_r.
  \end{cases}
\]
An enclosing residue already covers levels at or below \(l_r\).

A filter or residue wrapping a \emph{value} is itself a redex,
always marked \(\ActSkip\) (\textsc{D-Filter-E},
\textsc{D-Residue-E}). These cases return the whole wrapper in the
original context, so \textsc{T-Filter} and \textsc{T-Residue} can
remove it.

\jbox{\(\StackDecompose{(\Phi,s)}{e}{\mathcal{E}'}{e_0}{(a',l_a')}\)}
Under filter stack \(\Phi\) and state \(s\), expression \(e\)
decomposes into context \(\mathcal{E}'\) with redex \(e_0\) and
action \(a'\) at level \(l_a'\).

Here, \(s=(a,l_a,l_r,\mathcal{E})\), and \(t\) is an action--level pair.
\begin{mathpar}
  % Application
  \inferrule[D-Ap-L]{
    \Lookup{\Phi}{e_1(e_2)}{s}
      =(a',l_a',l_r',\mathcal{E}') \\
    \StackDecompose{(\Phi,(a',l_a',l_r',
      \Plug{\mathcal{E}'}{\Mark(e_2)}))}{e_1}{\mathcal{E}''}{e_0}{t}
  }{
    \StackDecompose{(\Phi,s)}{e_1(e_2)}{\mathcal{E}''}{e_0}{t}
  }
\end{mathpar}
\begin{mathpar}
  \inferrule[D-Ap-R]{
    \Lookup{\Phi}{e_1(e_2)}{s}
      =(a',l_a',l_r',\mathcal{E}') \\
    \StackDecompose{(\Phi,(a',l_a',l_r',
      \Plug{\mathcal{E}'}{e_1(\Mark)}))}{e_2}{\mathcal{E}''}{e_0}{t}
  }{
    \StackDecompose{(\Phi,s)}{e_1(e_2)}{\mathcal{E}''}{e_0}{t}
  }
\end{mathpar}
\begin{mathpar}
  \inferrule[D-Ap-E]{
    \Value{v_1} \\ \Value{v_2} \\
    \Lookup{\Phi}{v_1(v_2)}{s}
      =(a',l_a',l_r',\mathcal{E}')
  }{
    \StackDecompose{(\Phi,s)}{v_1(v_2)}{\mathcal{E}'}
      {v_1(v_2)}{(a',l_a')}
  }
\end{mathpar}
\begin{mathpar}
  % Addition
  \inferrule[D-Add-L]{
    \Lookup{\Phi}{e_1+e_2}{s}
      =(a',l_a',l_r',\mathcal{E}') \\
    \StackDecompose{(\Phi,(a',l_a',l_r',
      \Plug{\mathcal{E}'}{\Mark+e_2}))}{e_1}{\mathcal{E}''}{e_0}{t}
  }{
    \StackDecompose{(\Phi,s)}{e_1+e_2}{\mathcal{E}''}{e_0}{t}
  }
\end{mathpar}
\begin{mathpar}
  \inferrule[D-Add-R]{
    \Lookup{\Phi}{e_1+e_2}{s}
      =(a',l_a',l_r',\mathcal{E}') \\
    \StackDecompose{(\Phi,(a',l_a',l_r',
      \Plug{\mathcal{E}'}{e_1+\Mark}))}{e_2}{\mathcal{E}''}{e_0}{t}
  }{
    \StackDecompose{(\Phi,s)}{e_1+e_2}{\mathcal{E}''}{e_0}{t}
  }
\end{mathpar}
\begin{mathpar}
  \inferrule[D-Add-E]{
    \Value{v_1} \\ \Value{v_2} \\
    \Lookup{\Phi}{v_1+v_2}{s}
      =(a',l_a',l_r',\mathcal{E}')
  }{
    \StackDecompose{(\Phi,s)}{v_1+v_2}{\mathcal{E}'}
      {v_1+v_2}{(a',l_a')}
  }
\end{mathpar}
\begin{mathpar}
  % Fixpoint
  \inferrule[D-Fix-E]{
    \Lookup{\Phi}{\Fix{x}{e}}{s}=(a',l_a',l_r',\mathcal{E}')
  }{
    \StackDecompose{(\Phi,s)}{\Fix{x}{e}}{\mathcal{E}'}{\Fix{x}{e}}{(a',l_a')}
  }
\end{mathpar}
\begin{mathpar}
  % Filter
  \inferrule[D-Filter-T]{
    \StackDecompose{(f::\Phi,(a,l_a,l_r,
      \Plug{\mathcal{E}}{\Filter{f}{\Mark}}))}{e}{\mathcal{E}'}{e_0}{t}
  }{
    \StackDecompose{(\Phi,s)}{\Filter{f}{e}}{\mathcal{E}'}{e_0}{t}
  }
\end{mathpar}
\begin{mathpar}
  \inferrule[D-Filter-E]{\Value{v}}{
    \StackDecompose{(\Phi,s)}{\Filter{f}{v}}{\mathcal{E}}{\Filter{f}{v}}
      {(\ActSkip,l_a)}
  }
\end{mathpar}
\begin{mathpar}
  % Residue
  \inferrule[D-Residue-T]{
    \Bump{(a,l_a)}{(a_r,l)}=(a',l_a') \\
    \Keep{l_r}{(a_r,l)}{\mathcal{E}}=\mathcal{E}_k \\
    \StackDecompose{(\Phi,(a',l_a',\max(l_r,l),\mathcal{E}_k))}
      {e}{\mathcal{E}'}{e_0}{t}
  }{
    \StackDecompose{(\Phi,s)}{\Residue{a_r}{l}{e}}{\mathcal{E}'}{e_0}{t}
  }
\end{mathpar}
\begin{mathpar}
  \inferrule[D-Residue-E]{
    \Value{v} \\ \Bump{(a,l_a)}{(a_r,l)}=(a',l_a')
  }{
    \StackDecompose{(\Phi,s)}{\Residue{a_r}{l}{v}}{\mathcal{E}}
      {\Residue{a_r}{l}{v}}{(\ActSkip,l_a')}
  }
\end{mathpar}

With \(\StripResidues{e}\) erasing residues while keeping filters,
the mechanization proves
\[
 \StackDecompose{(\Phi,s)}{e}{\mathcal{E}'}{e_0}{t}
 \quad\Longrightarrow\quad
 \StripResidues{\Plug{\mathcal{E}'}{e_0}}
 =\StripResidues{\Plug{\mathcal{E}}{e}},
\]
where \(\mathcal{E}\) is the context component of \(s\).

\subsubsection{Composition.} Composition plugs a redex (or the result
of an instruction transition) back into the hole of an evaluation
context. Unlike decomposition, it does not change any residues. The
full rules are given in Appendix~\ref{sec:standard_rules}.

\jbox{\(\Compose{e}{\mathcal{E}}{e_0}\)} Expression \(e\) is the
result of plugging \(e_0\) into the hole of \(\mathcal{E}\).

\subsubsection{Instruction transitions.} An instruction transition
reduces a single redex in isolation. Function application
substitutes the argument value into the body. Addition reduces to
the numerical sum. Fixpoint unrolls by substituting itself for its
bound variable. Filter and residue wrappers that surround a value
are removed: they have served their purpose once the surrounded
expression has finished evaluating. Substitution \(\FSubst{v}{x}{e}\)
is capture-avoiding; \(v\) need not be a value, since fixpoint
unrolling substitutes the fixpoint itself. Substitution also acts on
filter patterns, converting the substituted expression to a pattern.
Both are defined in Appendix~\ref{sec:standard_rules}.

\jbox{\(\Transition{e}{e'}\)} Expression \(e\) takes an instruction transition to \(e'\).
\begin{mathpar}
  \inferrule[T-Ap]{
    \Value{e_2}
  }{
    \Transition{(\Lam{x}{e_1})(e_2)}{\FSubst{e_2}{x}{e_1}}
  } \qquad
  \inferrule[T-Add]{
    \Value{n_1} \\
    \Value{n_2} \\
    n_1 + n_2 = n
  }{
    \Transition{\Nat{n_1} + \Nat{n_2}}{\Nat{n}}
  } \\
  \inferrule[T-Fix]{
    \
  }{
    \Transition{\Fix{x}{e}}{\FSubst{\Fix{x}{e}}{x}{e}}
  } \\
  \inferrule[T-Residue]{
    \Value{v}
  }{
    \Transition{\Residue{a}{l}{v}}{v}
  } \qquad
  \inferrule[T-Filter]{
    \Value{v}
  }{
    \Transition{\Filter{f}{v}}{v}
  }
\end{mathpar}

\subsubsection{Stepping.} With all the pieces in place, the
top-level stepping judgment ties decomposition, transition, and
composition together. \textsc{S-Step} fires when decomposition yields
a candidate with action \(\ActStep\) and \emph{no} candidate has
action \(\ActSkip\); the step is then shown to the user.
\textsc{S-Skip} covers the silent case, performing the step silently
and continuing stepping recursively. Filter and residue eliminations
are always marked \(\ActSkip\), so they are always silent. After every
reduction, decomposition starts again from \(\TopState\), allowing
enclosing expressions to match newly applicable filters.

\jbox{\(\FilteredStep{e}{e'}\)} Expression \(e\) takes a filtered step to \(e'\).
\begin{mathpar}
  \inferrule[S-Step]{
    \StackDecompose{\TopState}{e}{\mathcal{E}_0}{e_0}{(\ActStep,l)} \\
    \neg\bigl(\exists\mathcal{E}_1,e_1,l_1.\;
    \StackDecompose{\TopState}{e}{\mathcal{E}_1}{e_1}{(\ActSkip,l_1)}\bigr) \\
    \Transition{e_0}{e_t} \\
    \Compose{e'}{\mathcal{E}_0}{e_t}
  }{
    \FilteredStep{e}{e'}
  } \\
  \inferrule[S-Skip]{
    \StackDecompose{\TopState}{e}{\mathcal{E}_0}{e_0}{(\ActSkip,l)} \\
    \Transition{e_0}{e_t} \\
    \Compose{e_1}{\mathcal{E}_0}{e_t} \\
    \FilteredStep{e_1}{e'}
  }{
    \FilteredStep{e}{e'}
  } \\
  \inferrule[S-Value]{
    \Value{v}
  }{
    \FilteredStep{v}{v}
  }
\end{mathpar}

The relation leaves the choice among silent candidates unspecified;
the reference implementation selects the first in left-to-right order.

\subsection{Static Semantics}\label{sec:statics}

For the metatheory below, we equip the calculus with a simple type
system. The type grammar adds natural numbers and arrows. The rest
of the syntactic categories from \autoref{fig:filter-syntax} are
unchanged.

    \begin{array}{rcl}
      \DefTyp \tau &\Coloneqq& \Natural \mid \Arrow{\tau}{\tau}
    \end{array}

The expression typing judgment \(\TypeEntails{\Gamma}{e}{\tau}\)
threads a typing context \(\Gamma\) of variable bindings through the
expression in the standard way. Filter and residue wrappers are
transparent to typing: they preserve the body's type. Patterns are
typed by a separate but analogous judgment so that we can require
patterns to be closed and well-typed in their declaration
context. The two pattern wildcards \(\PatExpr\) and \(\PatValue\)
may be assigned any type; matching separately enforces the value
restriction of \(\PatValue\).

\jbox{\(\TypeEntails{\Gamma}{e}{\tau}\)} Under typing context \(\Gamma\), expression \(e\) has type \(\tau\).

  \inferrule[TE-Var]{
    \TypeContains{\Gamma}{x}{\tau}
  }{
    \TypeEntails{\Gamma}{x}{\tau}
  } \qquad

  } \\

  } \qquad
  \inferrule[TE-Fix]{

\subsection{Properties}

Because the Filtered Stepper Calculus layers filter and residue
annotations on top of a standard reduction calculus, we want to
confirm that these additions are \emph{conservative}: they should
not break the guarantees of the underlying language. Preservation
(Theorem~\ref{thm:preservation}) ensures that every intermediate
state the stepper shows the user has the same type as the original
expression, so the displayed evaluation remains coherent. Progress
(Theorems~\ref{thm:progress} and~\ref{thm:single-iteration}) ensures
that the stepper does not introduce new stuck states for well-typed
programs. Simulation (Theorem~\ref{thm:simulation}) ensures that
filtering introduces no computations beyond those of the base
lambda calculus.

\begin{theorem}[Preservation]\label{thm:preservation}
  If \(\TypeEntails{\varnothing}{e}{\tau}\) and \(\FilteredStep{e}{e'}\), then \(\TypeEntails{\varnothing}{e'}{\tau}\).
\end{theorem}

\begin{theorem}[Decomposition Progress]\label{thm:progress}
  If \(\TypeEntails{\varnothing}{e}{\tau}\), then either \(e\) is a
  value or there exist \(\mathcal{E},e_0,a,l\) such that
  \(\StackDecompose{\TopState}{e}{\mathcal{E}}{e_0}{(a,l)}\).
  Values admit no decomposition.
\end{theorem}

A natural stronger statement, ``every well-typed expression either
is a value or takes a visible filtered step,'' is \emph{not}
provable in general. Under a filter that hides every step (e.g.,
\code{debug eval(\$e)}) applied to a divergent program, the stepper
takes no user-visible action, and there is no finite filtered
derivation to construct. What does hold is \emph{single-iteration
progress} (Theorems~\ref{thm:progress}
and~\ref{thm:single-iteration}): every well-typed non-value admits an
iteration of decomposition, transition, and composition. This is the
precise guarantee that ``the step button always does something'' even
when no visible step results.

\begin{theorem}[Transition Progress]\label{thm:single-iteration}
  If \(\TypeEntails{\varnothing}{e}{\tau}\) and
  \(\StackDecompose{\TopState}{e}{\mathcal{E}}{e_0}{t}\), then there
  exists \(e_0'\) such that \(\Transition{e_0}{e_0'}\).
\end{theorem}

To state the simulation theorem, we define an unfiltered stepping
judgment on expressions without filter and residue wrappers, together
with its reflexive--transitive closure \(\JustStepStar{e}{e'}\). Here
\(\mathcal{E}\) ranges over contexts built from the hole, application,
and addition, and \(e_0\) takes one of \textsc{T-Ap}, \textsc{T-Add},
or \textsc{T-Fix}.

\jbox{\(\JustStep{e}{e'}{1}\)} Expression \(e\) takes one unfiltered step to \(e'\).
\begin{mathpar}
  \inferrule[J-Step]{
    \Transition{e_0}{e_0'}
  }{
    \JustStep{\Plug{\mathcal{E}}{e_0}}{\Plug{\mathcal{E}}{e_0'}}{1}
  }
\end{mathpar}

\jbox{\(\JustStepStar{e}{e'}\)} Expression \(e\) takes zero or more unfiltered steps to \(e'\).
\begin{mathpar}
  \inferrule[J-Refl]{ }{
    \JustStepStar{e}{e}
  } \qquad
  \inferrule[J-Trans]{
    \JustStep{e}{e_1}{1} \\
    \JustStepStar{e_1}{e'}
  }{
    \JustStepStar{e}{e'}
  }
\end{mathpar}

\begin{theorem}[Simulation]\label{thm:simulation}
  If \(\FilteredStep{e}{e'}\), then \(\JustStepStar{\Strip{e}}{\Strip{e'}}\).
\end{theorem}

Each computational transition the stepper takes corresponds to one
unfiltered step of the stripped program, while removing a filter or
residue around a value corresponds to zero steps. We do not record
these counts in the statement, since the corollary we care about, that
the stepper does not invent reductions, follows from the existence of
any such derivation.

\paragraph*{Residue invariants and bounds.}
Decomposition never visits a binder body. Starting from a program with
no residues, every reachable residue names an in-scope persistent filter at
the same level with the same action; no residue
occurs beneath a lambda or fixpoint binder. This invariant is preserved
by decomposition, transitions, and filtered steps.

\begin{theorem}[Residue Bounds]\label{thm:residue-bounds}
 In a decomposition from \(\TopState\), newly inserted residue
 levels strictly increase along the path to the redex and are
 bounded by the number of filters in scope there. The levels of
 all residues retained or inserted along that path also strictly
 increase. If \(N_\delta(e)\) and \(N_\phi(e)\) count residues and
 filters in an expression, respectively, then
 \[
  \StackDecompose{\TopState}{e}{\mathcal{E}}{e_0}{t}
  \quad\Longrightarrow\quad
  N_\delta(\Plug{\mathcal{E}}{e_0})
  \leq N_\delta(e)+N_\phi(e).
 \]
\end{theorem}
For states reachable from source programs, the invariant additionally
bounds retained residue levels by the filter stack depth, so each
returned path contains at most one residue per filter in scope. These
bounds concern an individual candidate context before transition.

\subsection{Agda Mechanization}

We mechanize the dynamic and static semantics of the calculus,
together with proofs of preservation, progress, simulation, and the
residue bounds as stated above. We use de Bruijn indices for
expressions and patterns to handle \(\alpha\)-equivalence during
filter matching. We fuse substitution with removal of the substituted
binder, avoiding a separate downward-shift operation.
